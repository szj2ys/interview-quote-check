Interview Quote Check

Offline developer utility · Python standard library

For people building or reviewing AI interview reports

Check quotes against the turn they cite.

Catch altered quotations and wrong-turn references before treating quoted text as report evidence.

This small CLI checks exact text membership. It does not judge whether an answer is true, whether feedback is fair, or whether a candidate should be hired. Run it locally with Python 3.10 or newer; no API key, package installation, upload, or account is required.

Start with the synthetic examples

Download the project repository, or save quote_check.py and the example files locally. All bundled scenarios are explicitly fictional teaching data. From the project folder, run:

python quote_check.py examples/valid.json
python quote_check.py examples/altered-quote.json
python -B -m unittest discover -s tests -v

The first command exits 0; the second exits 1 because the quotation was changed. A mismatch is useful output, not a crash. The test command runs the supplied schema, matching, Unicode, privacy-output, and subprocess checks. See the README for stdin usage and the full contract.

Give every turn an explicit identifier

The input is one UTF-8 JSON object with exactly transcript and evidence. Both are nonempty arrays. A transcript item has turn_id and text; an evidence item has turn_id and quote. IDs must be unique in the transcript. IDs and quotes must be nonblank strings. The checker rejects duplicate IDs, unknown keys, invalid types, and empty evidence before producing quote results.

{
  "transcript": [
    {"turn_id": "answer-1", "text": "I wrote the import script."}
  ],
  "evidence": [
    {"turn_id": "answer-1", "quote": "wrote the import script"}
  ]
}

Keep the original transcript and the report quote separate. If your report uses a paraphrase, translation, or ellipsis, label it as such rather than passing it off as an exact quotation. This validator intentionally does not repair text to make a quotation pass.

Example 1: an exact quote passes

Fictional scenario: a candidate describes writing an import script, credits a colleague for reviewing retries, and then describes postponing a launch. The two quotations below preserve the original wording and cite the correct turns.

{
  "transcript": [
    {"turn_id": "answer-1", "text": "I wrote the import script. Maya reviewed the retry logic."},
    {"turn_id": "answer-2", "text": "We postponed the launch until the duplicate records were checked."}
  ],
  "evidence": [
    {"turn_id": "answer-1", "quote": "I wrote the import script."},
    {"turn_id": "answer-2", "quote": "We postponed the launch"}
  ]
}

Run the included valid.json fixture:

python quote_check.py examples/valid.json

Actual CLI output for that fixture, exit 0:

{"status":"pass","checked":2,"matched":2,"results":[{"check_id":1,"status":"match","reason":"exact_substring"},{"check_id":2,"status":"match","reason":"exact_substring"}]}

The second quote is shorter than the full answer, which is allowed: it is an exact substring of the cited turn. “Pass” means these two supplied quotations match. It does not verify the candidate’s contribution or prove that shortening the answer preserved its full context.

Example 2: a stronger claim fails

Fictional scenario: a candidate said they helped review a script. A report presents them as its author. The wording is plausible, but it is not the wording in the supplied turn.

{
  "transcript": [
    {"turn_id": "answer-1", "text": "I helped review the import script."}
  ],
  "evidence": [
    {"turn_id": "answer-1", "quote": "I wrote the import script."}
  ]
}

Run the included altered-quote.json fixture:

python quote_check.py examples/altered-quote.json

Actual CLI output for that fixture, exit 1:

{"status":"mismatch","checked":1,"matched":0,"results":[{"check_id":1,"status":"mismatch","reason":"quote_not_in_turn"}]}

Find evidence item 1 in your input and inspect its source. Correct the quotation or the turn mapping; do not weaken the checker until the fabricated sentence passes. If the same quote exists in another turn, it still fails against this turn. Try wrong-turn.json to see that boundary.

Three exit codes, three different next steps

0 — all supplied quotes match
Continue to context, attribution, and coaching review. No quality or hiring judgement is implied.
1 — at least one mismatch
Inspect the indexed evidence item. missing_turn means its identifier was absent; quote_not_in_turn means the identifier existed but the text did not match.
2 — input cannot be checked
Repair the invocation, file access, UTF-8 encoding, JSON syntax, or schema. Malformed JSON and empty evidence are errors, not successful reports.

Output includes one-based check positions, statuses, and reasons. It does not repeat your transcript, quote text, identifiers, or file paths. Check both the exit code and the result. A missing process result must never silently become “all quotes passed.”

Text that looks the same may still differ

Matching compares Unicode codepoints after JSON decoding. A capital letter differs from a lowercase letter. A curly apostrophe differs from a straight apostrophe. Two spaces differ from one. The accented character in café can also be represented as an e followed by a combining accent; those are different sequences. The tool performs no Unicode normalization, case folding, trimming, or fuzzy matching.

Run unicode.json: five evidence items produce two exact matches and three mismatches, with exit 1. This strictness helps preserve quotation fidelity. If your upstream system intentionally transforms text, retain that transformation as a separately documented step and compare against the correct original source.

What an exact match cannot establish

A quote can pass and still mislead. For example, I led the migration is a substring of I never said I led the migration. The checker has no understanding of negation, completeness, speaker identity, consent, or whether an answer is true. A fabricated transcript can contain a fabricated quote. A transcription error can be quoted perfectly. Read the surrounding turn, confirm its provenance, and compare disputed wording with authorised source audio when available.

That makes it a useful example of why text membership and audio accuracy are different questions. This link is contextual reading, not an endorsement, a validation result, or a claim that this utility has checked that report.

The utility reads the supplied document into memory and makes no network calls, analytics requests, or storage writes. Your operating system, shell, backups, or caller may still retain data. Avoid putting private transcript text directly in shell commands. This small tool does not cap input size or provide a hardened upload service; use appropriately sized local files.

Keep the project offline

The CLI, fixtures, tests, and this documentation work without an internet connection. The repository and hosted tutorial are two views of the same resource. There is no browser upload box or automatic connection to a live interview service. Inspect the source and the tests before integrating the checker into your own report pipeline.
